ComptaJLC – Principes de fonctionnement

Référentiels · Paramètres Excel · Imports et exports · Base de données · Installation · Contrôles · Banque

Ce document explique comment l'application tient ensemble. Cinq mécanismes en sont la base : les référentiels (ce que l'on peut choisir en saisie), les paramètres (réglés dans Excel), les échanges de fichiers (imports et exports), la base de données (avec ses sauvegardes et ses archives) et le cycle installation / mise à jour du site. Les menus cités sont ceux de l'application ; les quatre premiers sont réservés à l'administrateur (certains au trésorier).

L'idée directrice. Rien de propre à l'association n'est écrit dans le programme : noms, comptes, journaux, codes, modèles d'opérations, traductions sont des données. On les modifie dans l'application ou dans Excel, jamais dans le code. Le programme (le « site ») se remplace par une mise à jour ; les données restent là où elles sont et sont sauvegardées avant chaque changement important.

1. Administration › Référentiels

Le principe

Un référentiel est une liste de valeurs autorisées, créée une fois, que la saisie propose ensuite. On ne tape pas un compte ou un code de mémoire : on le choisit. Cela évite les fautes de frappe et garantit que chaque écriture ne cite que des éléments qui existent.

RéférentielRôleOù le gérer
Plan comptableLes comptes (512000 banque, 600000 achats…). Chaque compte porte obligatoirement un code d'axe 1 (sa nature).Saisie › Plan comptable
Axe 1 – natureCe que sont les sommes : cotisations, fonctionnement, bilan (BIL)…Saisie › Codes des axes 1 et 2
Axe 2 – événement, projetÀ quoi servent les sommes : un rallye, un gala, une bourse. Codes proposés par l'application (préfixe + numéro suivant) ; l'utilisateur ne saisit que le libellé.Saisie › Codes et nouveaux tiers
JournauxBanques et caisses (B1, CA…), achats, ventes, opérations diverses, à-nouveaux.Administration › Journaux
TiersMembres (411…), fournisseurs (401…) : un compte par tiers.Tiers › Liste des tiers
Utilisateurs et rôlesAdministrateur, trésorier, bureau, bénévole.Administration › Utilisateurs
Modèles, moyens de paiement, traductions…Types d'opérations de la saisie guidée, banques et caisses proposées, traduction des relevés en hébreu.Administration › Paramètres (Excel)

Les règles d'affectation des axes

  • Axe 1 = le compte. Un compte porte toujours un code d'axe 1 (jamais un code d'axe 2) ; les écritures en héritent. Un compte sans code d'axe 1 est refusé dans le plan, à l'import, et signalé par les Contrôles.
  • Axe 2 = l'écriture. Une écriture ne reçoit qu'un code d'axe 2 (jamais un code d'axe 1), et seulement sur un compte de charges (6) ou de produits (7). Les comptes de bilan (classes 1 à 5) n'ont pas d'axe 2.
  • Fonctionnement ou projet. Pour une même nature de dépense ou de recette, on ouvre deux comptes : l'un pour le fonctionnement courant (ex. 600000), l'autre pour les projets (ex. 600001, coché « Compte de projet »). Toute écriture sur un compte de projet doit porter un code d'axe 2 ; le compte de fonctionnement n'en exige pas.
Rien n'est supprimé d'un référentiel utilisé par des écritures : on le désactive (« Proposé en saisie » décoché). Chaque création ou modification est inscrite dans Contrôle › Historique.

2. Administration › Paramètres (Excel)

Le principe

Tous les paramètres tiennent dans un seul classeur, Parametres.xlsx, une feuille par table : Réglages, Axe 1, Axe 2, Préfixes, Plan comptable, Journaux, Types de tiers, Moyens de paiement, Schémas, Modèles d'opération, Natures et modes des fiches, Relevés, Traductions. On l'exporte, on le modifie dans Excel (copier-coller de dizaines de lignes d'un coup), puis on le réinjecte.

  1. Télécharger Parametres.xlsx (Administration › Paramètres (Excel)) ; une copie reste dans le dossier Exports.
  2. Modifier dans Excel, sans changer les en-têtes de colonnes ni l'ordre des feuilles.
  3. Envoyer le fichier : l'application le contrôle, puis l'applique.

Les règles de l'import

SituationEffet
La clé de la ligne existeL'élément est mis à jour. La clé est en colonne grise (Compte, Code, Journal…).
La clé est nouvelleL'élément est créé.
Cellule videRien n'est remplacé.
Ligne absente du fichierRien n'est supprimé. Pour retirer un élément : Actif = Non.
Une seule erreurTout ou rien : rien n'est enregistré ; le rapport liste chaque ligne à corriger (feuille, ligne, motif).
Dans tous les casUne sauvegarde de la base est faite juste avant ; chaque changement est inscrit dans l'Historique.

Les comptes de tiers n'y figurent pas : ils ont leur fichier Tiers.xlsx. Un fichier venu d'une autre application de comptabilité n'est jamais lu tel quel : l'administrateur l'adapte d'abord à cette structure (Power Query ou macro dans Excel).

3. Administration › Imports et exports

Le principe

Les échanges avec l'extérieur se font par fichiers Excel (.xlsx) dont la structure est fixée (colonnes décrites dans Lexique.xlsx, livré avec les modèles vierges). L'application ne lit ni PDF ni format de banque : le fichier est préparé en amont, puis importé.

DossierContenu
ImportsLes fichiers à importer, déposés depuis le navigateur (« Déposer »). Le fichier est reconnu d'après les colonnes de sa ligne 1, quel que soit son nom.
ExportsCe que l'application écrit : exports, Parametres.xlsx téléchargé, états.
Exports/SauvegardesCopies de la base (voir § 4).
Exports/ArchivesClasseurs figés des clôtures, copies de l'historique effacé.

Les formats reconnus

Exercices · Réglages · Axe 1 · Axe 2 · Préfixes · Plan comptable · Axes de comptes · Journaux · Tiers · Traductions · Budget · Écritures · Libellés · Liens des documents · Banque (relevés de toutes les banques et caisses).

Importer

  • Tout importer traite les fichiers déposés dans l'ordre du lexique : chaque fichier ne cite que des codes définis par les précédents (les axes avant le plan comptable, le plan avant les écritures).
  • Tout ou rien : une erreur dans une ligne et rien n'est importé ; une sauvegarde précède chaque import ; les référentiels sont mis à jour, jamais supprimés.
  • Les écritures importées sont contrôlées comme les écritures saisies : un débit OU un crédit par ligne, mouvements équilibrés, exercice non clos, codes existants, axe 2 réservé aux comptes 6 et 7 (un code d'axe 1 en axe 2 est refusé). Un nouveau compte doit porter son code d'axe 1.
  • Un Mvt déjà présent et inchangé est ignoré (aucun doublon) ; un Mvt modifié est mis à jour avec l'avant / après dans l'historique.

Exporter

Exporter des données (menu Éditions) donne un fichier par référentiel ou nature de données, ou tout dans un .zip avec Parametres.xlsx et Lexique.xlsx. Un fichier exporté se réimporte tel quel : on peut donc corriger dans Excel puis réinjecter.

Attention. Un fichier Écritures, Banque ou Budget importé par « Tout réinjecter » remplace toutes les données de sa nature (ce qui n'est plus dans le fichier est supprimé) ; il faut taper REMPLACER pour confirmer. L'import ordinaire, lui, n'efface rien.

4. Administration › Base de données : exports complets et sauvegardes

Le principe

Toute la comptabilité est dans une seule base de données (un fichier comptajlc.sqlite3 dans le dossier de données du site). Elle est protégée de trois façons complémentaires, toutes visibles sur la page Administration › Base de données :

ProtectionCe que c'estOù est-ce rangé
SauvegardeCopie datée et cohérente de la base (même pendant que le site tourne), faite à la demande, avant chaque import, chaque remise à zéro et chaque mise à jour. Les 3 dernières sont gardées.Exports/Sauvegardes, sur le site
Export completUn .zip : base, Parametres, Tiers, Écritures, Données (budget, relevés, fiches, historique), justificatifs (scans et photos) et états de chaque exercice. Il est lisible dans Excel, donc indépendant du logiciel.Exports ; à télécharger et ranger sur le PC ou OneDrive
ArchivesClasseur Excel figé en valeurs à chaque clôture d'exercice, et copie de l'historique avant effacement. Lecture seule, preuve de l'exercice clos.Exports/Archives, sur le site

Que faire, et quand

  • Chaque mois, et avant une clôture : « Créer une sauvegarde », puis « Tout exporter » et télécharger le .zip sur le PC.
  • Une sauvegarde sur le site ne suffit pas : elle disparaît avec le site. Seul l'export téléchargé hors du site protège d'une perte de l'hébergement.
  • Restaurer ou recharger : « Remettre à zéro et recharger » accepte une sauvegarde (.sqlite3 : la base redevient exactement celle de la sauvegarde, comptes utilisateurs compris), un export complet (.zip : la comptabilité est vidée puis rechargée depuis ses fichiers Excel, puis comparée au fichier de contrôle ; au moindre écart, rien n'est modifié) ou, pour une reprise, le classeur ComptaJLC.xlsm. Pour un export dont les fichiers Excel ont été modifiés, cocher « Fichiers modifiés » : la base est alors vérifiée par les contrôles de cohérence.
  • Sécurité de l'opération : il faut taper REMPLACER pour confirmer ; une sauvegarde de la base actuelle est faite juste avant, on peut donc tout annuler en la rechargeant.
Les écritures ne se modifient ni ne se suppriment « en douce » : une correction passe par l'application (trésorier), jamais dans un exercice clos, avec l'avant / après conservé dans l'Historique. Les contrôles (Contrôle › Contrôles) vérifient l'équilibre, les axes, les exercices clos et les comptes d'attente ; leur résultat doit être « OK » avant toute clôture.

5. Installation et mise à jour

Le principe : un site par association

ComptaJLC est un site hébergé chez PythonAnywhere : rien à installer sur les ordinateurs, on s'y connecte par internet (connexion chiffrée). Le code (dossier ComptaJLC) et les données (dossier comptajlc-data : base, Imports, Exports, justificatifs) sont séparés : une mise à jour remplace le code et ne touche jamais aux données. Chaque association a son propre site, son propre compte d'hébergement, sa licence ; ce qui lui est propre (nom, devise, journaux, traductions) est dans les réglages, pas dans le code.

Installer un site neuf (une seule fois)

  1. Sur PythonAnywhere : onglet Web › Add a new web app › Manual configuration.
  2. Envoyer le ZIP de ComptaJLC (téléchargé depuis GitHub) dans Files.
  3. Dans une console Bash : unzip -qo ComptaJLC-*.zip -d ~/inst && bash ~/inst/*/appli/deploiement/installer.sh Le script installe le code, l'environnement Python, la base vide et le fichier WSGI, puis affiche un code d'installation.
  4. Régler l'onglet Web (version de Python, virtualenv, fichiers statiques /static/, HTTPS forcé), cliquer Reload.
  5. Ouvrir le site : l'assistant « Bienvenue dans ComptaJLC » demande le code, crée l'administrateur, puis guide le paramétrage de base.

Mettre à jour

  1. Télécharger le ZIP de la branche indiquée sur GitHub (<> Code › Download ZIP).
  2. L'envoyer dans Files, dossier de l'utilisateur (le nom doit commencer par ComptaJLC-).
  3. Dans une console Bash : bash ~/maj.sh
  4. Le script enchaîne 5 étapes : (1) sauvegarde de la base et copie des justificatifs, (2) installation du nouveau code (l'ancien est gardé dans ComptaJLC-ancien), (3) bibliothèques Python, (4) migration de la base et des paramètres, (5) rechargement du site. Il se termine par « MISE À JOUR TERMINÉE ».
  5. Ouvrir le site et appuyer sur Ctrl+F5.
En cas de problème : bash ~/maj.sh --retour remet le code précédent ; les données n'ont jamais été touchées, et les 3 dernières sauvegardes de la base sont listées par le script. Les corrections de données faites par une mise à jour (par exemple, retirer un code d'axe 2 d'une écriture de bilan) sont appliquées automatiquement à l'étape 4.

Ce qu'une mise à jour apporte avec elle

Le code, les migrations de la base, et les documents PDF du menu Éditions (Présentation, Mode d'emploi, Guide des bénévoles, Principes de fonctionnement) : ils sont livrés avec le code et donc toujours à jour. Les comptes de la comptabilité, les paramètres et les réglages ne sont jamais écrasés.

6. Contrôle › Contrôles

Le principe

La page Contrôle › Contrôles relit toute la comptabilité et vérifie des règles que l'application impose déjà à la saisie, au cas où une écriture serait arrivée autrement (import, reprise, ancienne version). Elle ne modifie rien : elle constate. Le bandeau du tableau de bord reprend son verdict : OK, ou « n anomalie(s) ». Une clôture d'exercice n'est possible que si tout est OK.

StatutSens
OKLa règle est respectée.
AnomalieUne règle est violée : à corriger (le détail liste les écritures ou comptes concernés, avec un lien vers le Mvt).
À vérifierPas une erreur certaine : par exemple un compte d'attente ou de virement interne dont le solde n'est pas nul.
InfoSimple indication (remboursements : recette au débit, dépense au crédit).

Ce qui est contrôlé

  • Équilibre : total débit = total crédit ; aucun mouvement déséquilibré ni de moins de deux lignes ; une ligne = un débit ou un crédit.
  • Axes : chaque compte porte un code d'axe 1 (et c'est bien un code d'axe 1) ; aucune écriture n'a un code d'axe 1 en axe 2 ni un axe 2 sur un compte de bilan ; toute écriture d'un compte « de projet » porte un code d'axe 2.
  • Exercices clos : aucune écriture nouvelle dans un exercice clos.
  • Comptes techniques : le compte de virement interne et le compte d'attente doivent revenir à zéro.
Corriger. Une écriture se corrige depuis l'application (Saisie › Modifier une écriture), jamais dans un exercice clos, avec l'avant / après dans l'Historique. Les anomalies d'axes les plus courantes (code d'axe 2 invalide, compte sans axe 1 repris d'un compte voisin) sont aussi corrigées automatiquement à chaque mise à jour, ou à la demande par la commande python manage.py corriger_axes (aperçu sans l'option --appliquer) ; chaque correction est inscrite dans l'Historique.

7. Banque › Relevés à passer en comptabilité

Le principe

Le relevé de la banque est la preuve de ce qui s'est réellement passé sur le compte. L'application le compare à la comptabilité : chaque ligne du relevé doit avoir une écriture, et une seule. Les lignes qui n'en ont pas encore sont listées sur cette page, par banque (un onglet par journal : B1, B2…). On ne tape jamais une écriture de banque à la main : on indique seulement la contrepartie, et l'application crée l'écriture à deux lignes (banque / contrepartie), aussitôt reliée à sa ligne de relevé, qui disparaît de la liste.

Déroulement

  1. Télécharger le relevé (« Télécharger un relevé… », en bas de page) : un fichier Excel ou CSV unique pour toutes les banques (colonnes Jnl, Date, Libelle, Debit, Credit, Solde facultatif), préparé en amont. Les lignes déjà connues sont ignorées : on peut reprendre un relevé qui chevauche le précédent, sans doublon.
  2. Relier celles déjà en compta : l'application relie d'elle-même les lignes dont une seule écriture de même montant existe déjà à quelques jours près (7 jours par défaut, réglage tolerance_rapprochement). Rien n'est créé ; les cas douteux restent dans la liste, avec des pistes (même montant plus ancien, autre banque, plusieurs écritures regroupées).
  3. Reprendre les propositions : l'application se souvient du compte utilisé pour un même libellé et le propose ; on l'accepte ligne à ligne ou pour toutes les lignes vides.
  4. Pour chaque ligne restante, choisir le compte de contrepartie (et le code axe 2 si le compte est de charges ou de produits) ; le libellé de l'écriture est modifiable.
  5. Créer les écritures : une écriture par ligne renseignée. Les lignes laissées vides restent à faire.
  6. Écarter une ligne déjà passée autrement (doublon, écriture d'une autre banque…) : elle quitte la liste sans écriture ; on peut la remettre plus tard.
La fenêtre est organisée du plus fréquent au plus rare : onglets des banques et titre sur une seule ligne, puis une barre d'actions (Créer, Reprendre les propositions, Relier, Écarter ▾), un « Comment faire ? » repliable, la liste, et enfin, repliés, le téléchargement du relevé et les paramètres de la banque (date de reprise : les lignes antérieures sont dans le solde d'ouverture et ne sont pas proposées).

8. Banque › Historique des imports

C'est le journal des fichiers de relevé téléchargés : date, banque, nom du fichier, nombre de lignes ajoutées, nombre de doublons ignorés, auteur. Il sert à retrouver quel fichier a apporté quelles lignes et à vérifier qu'un relevé n'a pas été repris deux fois (ses lignes apparaîtraient alors en « doublons ignorés », jamais en « ajoutées »).

Peut-on le supprimer ? Oui, ligne par ligne (cases à cocher puis « Supprimer les lignes cochées »). Ce n'est qu'un journal : supprimer une ligne n'enlève aucune ligne de relevé et aucune écriture, et n'empêche pas de reprendre le même fichier (les doublons restent écartés à chaque import). La suppression est inscrite dans l'Historique général.

9. Banque › Traductions du relevé

Les relevés arrivent en hébreu. Une traduction associe un libellé hébreu à son équivalent français ; elle s'applique ensuite à toutes les lignes identiques et devient le libellé proposé des écritures. La page liste les opérations « À traduire » avec un exemple (date, montant).

Propositions à valider. Pour chaque opération, l'application inscrit une proposition fondée sur un glossaire de termes bancaires courants (virement, commission, dépôt, retrait, chèque, électricité, assurance, cotisation…) et sur les traductions déjà validées. Ce n'est pas une traduction certaine : « à valider » signifie que tous les mots sont reconnus, « à compléter » que des mots hébreux restent. On lit, on corrige, puis Valider et enregistrer ; une case vidée n'enregistre rien.

Traduction automatique (API de Claude)

Si une clé d'API est installée, le bouton Proposer par traduction automatique apparaît : il envoie les libellés hébreux (40 au plus à la fois, sans montant ni date) à l'API de Claude et inscrit les traductions proposées dans les cases, sans rien enregistrer : on valide comme d'habitude. Sans clé, ou si le service est injoignable, le glossaire reste utilisé.

  1. Créer une clé sur console.anthropic.com (menu API keys), avec un peu de crédit sur le compte.
  2. Sur PythonAnywhere, onglet Files, dossier comptajlc-data : créer un fichier cle-claude.txt contenant seulement la clé. Ce fichier n'est ni dans la base, ni dans les exports, ni touché par les mises à jour. (Variante : variable d'environnement ANTHROPIC_API_KEY dans le fichier WSGI.)
  3. Recharger le site (onglet Web › Reload). L'accès sortant vers api.anthropic.com doit être autorisé par l'hébergement (liste blanche des comptes gratuits : à vérifier ; sinon, formule payante).
Les libellés de relevé quittent le site pour être traduits (noms de personnes compris). Ne pas activer si cela n'est pas acceptable pour l'association.
